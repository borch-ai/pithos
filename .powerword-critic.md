### Committed Changes Analysis

The committed diff adds powerword checkout steps but is **missing `token: ${{ secrets.PAT_TOKEN }}`** on those checkout steps. The private `borch-ai/powerword` repo cannot be checked out without authentication. This would cause CI failures.

However, the **uncommitted working tree** adds:
```yaml

```
to both powerword checkout steps. This fix exists but is not committed.

#### Data Race Fix (Uncommitted)
The previous critic correctly identified a data race: `m.Telemetry.ImageGenerations++` was unprotected in `brew.go`. The uncommitted working tree introduces `RecordLLMUsage` and `RecordImageGeneration` helper methods on `Manifest` that properly hold the mutex for all mutations. The committed `brew.go` still has the racy pattern, but the uncommitted working tree fixes this. These fixes are not committed.

- `RecordImageGeneration()` - increments counter under lock ✅
- `updateTotalCostLocked()` - internal helper that avoids double-locking ✅

#### Uncommitted `brew.go`
- Replaces the tracker reconstruction pattern with `m.RecordLLMUsage(modelName, tokenUsage, pricing)` ✅
- Replaces `m.Telemetry.ImageGenerations++` + `m.UpdateTotalCost()` with `m.RecordImageGeneration(pricing)` ✅

1. All `go.mod replace` directives for `github.com/borch-ai/*` have corresponding CI checkout steps
2. Those checkout steps include a `token:` secret

This hook would **reject the committed state** since the committed `ci.yml` lacks the token. The hook and the token addition to `ci.yml` are both uncommitted — they need to be committed together with the `ci.yml` token fix.

### Summary of Issues

1. **Critical — Uncommitted CI token**: `ci.yml` powerword checkout steps are missing `token: ${{ secrets.PAT_TOKEN }}` in the committed diff. Without this, CI will fail on private repo checkout. The fix exists in the working tree but is not committed.

2. **Critical — Data race uncommitted**: The committed `brew.go` has `m.Telemetry.ImageGenerations++` without holding the manifest mutex. The fix (`RecordImageGeneration`, `RecordLLMUsage`) exists in the uncommitted working tree but is not committed.

3. **Critical — Pre-push hook uncommitted**: The hook that enforces the above CI requirements is itself uncommitted, so the pre-push validation is not yet in place.

4. **`UpdateTotalCost` is now effectively dead code** in the committed state — it acquires the lock itself but `updateTotalCostLocked` (uncommitted) is the internal version. The committed `manifest.go` has `UpdateTotalCost` with an exposed lock that will conflict with `updateTotalCostLocked` in the uncommitted version. The test `TestUpdateHelpers` still references `UpdateTotalCost` via manifest_test.go (coverage: 0.0% per the output confirms `UpdateTotalCost` is not covered).

These are not cosmetic issues — three separate uncommitted changes are required for correctness and CI functionality.
